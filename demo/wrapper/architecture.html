Architecture

Where everything runs

The token boundary is the design: the browser never sees the Felt token, and the report and map both come from the same flattened GeoJSON, so the numbers cannot drift apart.

The engine

Abelian, in one slide

Open-source spatial analysis API: FastAPI over PostGIS, with scoring workflows for hazard and solar siting. Every assessment carries its data lineage. The repo holds the models, the methodology docs with citations, and now the portfolio pipeline this demo runs on.

What a hazard score returns

  • Wildfire and flood as separate perils, never one blended number
  • Annual expected loss in dollars per peril, plus a tier
  • Structure provenance: replacement value, building type, source
  • Per-criterion confidence, a composite tier, and named data gaps

Tiering, straight from the code

annual_risk_usd drives the tier:

HIGH  over $500/yr  ·  MODERATE  $50 to $500  ·  LOW  under $50

CANNOT ASSESS  is a first-class state when critical sources fail, not a silent zero.

Methodology · wildfire

Two paths to a wildfire number

Primary: validated loss model

Where features are pre-loaded, a logistic vulnerability model validated on Sonoma County outcomes scores each structure over USFS FSim burn probability, LANDFIRE fuel and canopy, and 3DEP terrain.

Fallback: transparent proxy

Everywhere else: NIFC historical fire frequency at the point, times LANDFIRE fuel-model and canopy damage factors, times the NSI replacement value. The response labels itself proxy_fallback and the popup carries a confidence note telling you to verify before relying.

What it looked like in North Bay

16 of 18 properties tiered HIGH, which is honest for post-Tubbs Sonoma and Napa. The discrimination lives in the dollars: $3K to $165K per year across the portfolio, driven by NSI replacement values. Each property also carries its actual fire history: Tubbs 2017, Nuns 2017, Hanly 1964, by name and acreage.

Methodology · flood

The HAZUS pipeline, per property

FEMA NFHL zone → classify (AE / A / X / D, SFHA flag, return period) USGS 3DEP ground elevation vs base flood elevation → water depth USACE NSI → structure match: occupancy class, first-floor height, value HAZUS depth-damage function → structural + contents loss → $/yr

North Bay result

Three properties sit in Zone AE: Napa Soscol Ave riverfront at $13,371/yr with a modeled $1.34M loss in a 100-year event, Napa Riverside Dr, and Guerneville Main St. Everything else in Zone X or D scored LOW with the zone stated.

No structure, no number

When NSI has no matched structure the response says so and the loss reads N/A. The Calistoga Silverado Trail site rendered as CANNOT ASSESS end to end: map popup, wrapper panel, PDF page.

Governance

The confidence layer is the product

A data-selection engine decides which sources are usable at each point before any scoring runs, and its verdict travels with the result. Per-criterion confidence, a composite tier, and named gaps flow untouched from the API to the Felt popup, to the wrapper's detail panel, to the PDF.

Why enterprise buyers care

  • Every dollar figure names its source (USACE NSI, by structure)
  • Proxy estimates say they are proxies, in the UI, verbatim
  • Gaps are listed, not smoothed over
  • Perils stay separate, so nobody averages fire against flood

The demo line

"The map your deal team is commenting on and the PDF your lender receives are the same governed record. Felt is where the argument happens; the lineage comes along for free."

Felt surface

What we used, what we hit

Used, and it held up

  • POST /maps then presigned S3 upload per portfolio
  • FSL categorical styling + popup schema (title, key attributes, renames)
  • view_and_comment so anyone with the link can mark up
  • JS SDK embed: setViewport fly-to on row click, onPointerClick back to the row
  • Map thumbnail on the PDF cover, linked to the live map

Gaps we designed around

  • No comment-create API. Read, resolve, delete, webhooks: yes. Seeding demo comments is a manual click.
  • No static render at a chosen viewport. The auto-framed thumbnail covers the PDF cover.
  • Row-level layer updates need Enterprise Live Data or a full re-upload, so each analysis publishes a fresh map.

The gaps are the interesting part internally: each one is a place a workflow product wants more surface from the platform.

Driving the app · 1 of 2

Upload to scored map

1 · open
portfolio-hazard-review.vercel.app. The North Bay portfolio loads as the default so the page is never empty.
2 · new portfolio
Click New portfolio, name it, attach a CSV. The sample CSV link next to the form shows the exact format.
3 · csv format
name, latitude, longitude or an address column for geocoding. 50 rows max, continental US. Bad rows get rejected with a plain-English reason before anything runs.
4 · watch
The status line reports the truth: "Scoring 9 of 19 properties", then "Publishing styled map to Felt". A cold Render instance announces itself instead of freezing. Rows that fail geocoding land in an errors note; the batch keeps going.
5 · done
The embed swaps to the new map, the list and summary recompute, and Open in Felt points at the new URL.
Driving the app · 2 of 2

Collaborate and export

Work the map

  • Click a row: the map flies to that property and the panel opens with both perils, fire history, provenance, gaps
  • Click a marker: the matching row highlights and the panel opens
  • Comment inside the embed or in Felt proper; comments persist on that map and support threads, mentions, resolve

Take it with you

  • Export PDF on the summary strip: cover with the live-map snapshot and a clickable link back, ranked exposure table, a page per property, methodology and disclaimer
  • Export property PDF in the detail panel for a single-site report

One caveat to narrate honestly: re-running a portfolio publishes a new map, so comment threads belong to the run they were made on. Each analysis is its own governed artifact.

Where it stands

Measured, and what productizing needs

Measured on the deployed stack

  • 3 properties: 39s end to end
  • 20 properties: 69s, including one live geocode and the Felt publish
  • North Bay portfolio: $1,091,357/yr combined estimated exposure across 18 sites
  • No Felt API rate or size limits encountered at this scale

Known v1 edges

  • Jobs live in process memory on one instance; a restart drops in-flight runs. Productizing wants a queue.
  • Maps accumulate one per analysis; a cleanup policy comes with real usage.
  • Nominatim geocoding runs at 1 req/s; a Mapbox token lifts that for address-heavy CSVs.

The thesis, restated: the moat is the canvas. Abelian supplies defensible numbers; Felt turns them into a place a deal team can stand. Everything here is on the felt-demo branch of the repo.
